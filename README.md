# Copilot Remote

> **独立三节点执行器**：新增 [`executor`](executor/README.md) 模块，采用
> “私网 A 运行 Copilot、私网 B 执行明确适配的工具、公网认证中继”的出站连接架构。
> 它有独立依赖、启动入口与授权边界，不改变本文原有手机网页/PC App 会话中继。
> 首版支持文件和进程工具，不代表原生 App 挂载或桌面/浏览器能力已全部远程化。

手机可用的 Copilot 风格会话列表与文本发送面板。目标是**现有 GitHub Copilot PC App 会话**，不是新建独立 CLI。手机选中只改变网页目标，不切换 PC 页面、不获取焦点、不模拟键鼠。

## 工作方式

认证网页 → 绑定专用 App 协调会话的项目扩展 → 优先通过内部 JSON-RPC（`session.tools.execute`）直接调用 App 原生工具，实现 **0 Token 消耗与毫秒级即时后台静默投递**；若底层环境不支持直接 RPC 执行，则自动平滑回退至协调会话模型转发。

通过内部 RPC 直接投递时，不触发协调助手模型回合，不消耗模型 Token 额度，不抢占焦点，且投递在毫秒级完成。若回退到模型转发，则需要一次模型执行。协调会话需要保持在 Copilot App 中打开；锁屏不影响后台投递，但电脑必须仍在运行，不能休眠。

状态严格区分：提交给协调助手、等待 App 回执、**App 已接受投递（可能排队）**、尚未执行投递的取消/失败、结果未知。App 接受不代表目标已处理，更不代表任务成功。网页投递回执与本机历史消息分开标记，不把回执伪装成助手回复。

## 本机历史与新回复

选中目标后，认证后端只读该会话 `events.jsonl` 的最近40条真实用户/助手消息；“加载更早记录”向前分页，每3秒增量读取已落盘的新回复，不需要模型中转，不恢复会话或改变PC焦点。查看旧消息时保持滚动位置，不强制跳到最新。用户与助手正文采用纯文本安全显示（Markdown源码保留，不执行HTML），自动续行/代理消息标记来源；附件仅显示安全名称，不开放本机路径、内容或下载。

此功能依赖本机内部持久化schema v1，**不是公开稳定的App历史API**。只允许真实目标列表中的ID，并核验同ID目录的`session.start.sessionId`及`context.cwd`与App目录一致；拒绝重解析/链接路径。若App ID不等于runtime ID、缺少本机目录、云端/远程或记录已删除，明确显示不可用，绝不搜索其它个人记录或猜路径。未知版本/消息结构、坏完整行均报错，不静默遗漏。除非空助手正文，还展示已成功执行的`task_complete`公开完成摘要（明确标记“完成摘要”）；尚未执行或失败的摘要不作为回复显示，其它原始工具日志不返回。

首次流式建立消息索引（40MB文件不反复全量解析），后续只读新增字节并核验文件身份、头/尾边界。按文件追加顺序分页，不按可能倒序的时间戳排序；固定快照内只解析完整换行记录。未落盘的流式片段不能读取，正在写的半行延后读取。文件截断/替换使旧游标失效，需点击“重新加载历史”。已在历史中出现的相同原文不会再次显示为网页用户气泡，但回执仍独立保留。这不是完整App UI的所有卡片/媒体/工具事件重放。

## 首次绑定与启动

需要 Windows、Node.js 22+ 和已登录的 Copilot PC App。生产代码没有 npm 依赖。绑定配置在 `.local\relay-probe-config.json`，其中 App ID 与 runtime ID 是分别验证的值，不能假定一致。

首次使用时，`.local\relay-probe-config.json` 不存在，项目扩展会提供一次性 `remote_relay_bind` 工具，而不是直接崩溃。请在 Copilot App 中打开本项目并新建一个专用聊天；在该聊天里先要求助手调用 `list_sessions_and_chats`，确认并记录当前聊天自己的精确 App session ID。确认 ID 后，再要求助手调用 `remote_relay_bind`，参数 `appId` 使用刚确认的 ID。绑定工具会自动记录扩展 runtime ID；不要手工猜测或复用其它聊天的 ID。

绑定成功后，在同一个聊天中执行 `extensions_reload`。扩展重载时会自动启动仅监听 `127.0.0.1:8765` 的控制服务；该聊天需保持在 Copilot App 中运行。之后双击根目录 `start.bat` 即可打开真实控制面板。`remote_relay_start` 仍可用于手动重启服务。若更换绑定聊天，先移走 `.local\relay-probe-config.json` 后重新完成绑定；不要让多个聊天同时争用服务端口。

访问 `http://127.0.0.1:8765`，首次在电脑本机页面创建自己的**独立本地账号和密码**（密码至少12位），之后使用账号密码登录。不会收集 GitHub 密码或 App token，也不再接受旧口令。`.local\account.json` 只保存用户名、随机盐和 scrypt 密码哈希，不保存明文密码。首次账号创建仅允许本机 loopback origin；请先在电脑配置账号，再设置手机代理。忘记本地密码时停止该服务并删除这一明确的账号文件，再重启并在本机重新创建；不要把密码发到聊天。

点击刷新会让协调助手通过真实 `list_sessions_and_chats` 列举现有目标；扩展直接解析工具 JSON 的 `project_id/project_name` 和 parent/creator 字段，显示 Chats、真实项目目录及嵌套会话。即使项目会话嵌套在聊天下，其真实项目文件夹仍会显示，不凭名称编造目录。列表有效期5分钟，发送前通过 `get_session` 核验精确目标。

“New”或 Projects 旁的“＋”可提交新建独立聊天或真实项目会话：协调助手只能调用精确参数的 App `create_session`（无 kickoff、任务、分支切换或导航），并查询新 ID 确认后才显示创建成功和新条目。未知结果不会自动重建。用户已通过此入口创建“测试”，实际 App 创建与查询回执保留在 ledger；开发测试不会另建会话。PR、Issues 等仅为灰色不可用的布局入口，不提供相关功能。

普通 `npm start`、`start.ps1` 和旧 UIA 桥接/测试仍然禁用，避免误启动已被用户拒绝的焦点输入方案。旧模拟输入代码已删除，相关入口只返回停用错误。

Windows 上双击根目录 `start.bat` 会检查真实服务 `http://127.0.0.1:8765` 是否已启动，启动后打开该控制面板；未完成绑定或服务未运行时会显示英文提示。脚本不会启动静态预览，也不会替代 App 扩展启动真实中继服务。

## 手机访问

默认仅 loopback。推荐已经配置的**私有 HTTPS 代理/VPN**转发到 `127.0.0.1:8765`，不要公开到互联网。在 `.local\relay-probe-config.json` 添加 `origin` 为浏览器实际使用的完整 HTTPS origin，重载协调器扩展并重新启动；代理必须保留同样的 Host。例如 `https://your-pc.your-tailnet.ts.net`。未配置代理时保持本机使用，不要关闭 Host/Origin 校验绕过问题。

本项目不安装/配置代理、防火墙或 VPN，手机不能用它自己的 `127.0.0.1` 访问电脑。代理方式必须实际配置和验证后才可宣称手机跨设备连接可用。HTTPS origin 的登录 Cookie 带 Secure，页面仍要求本地账号密码。服务不读取或暴露 App/GitHub token。

## 安全与可靠性边界

中转固定只做现有目标枚举、目标查询、原文后台投递及用户点击的新建空会话。网页无命令执行、创建任务、导航、远程桌面或回答权限提示接口。协调助手的 hooks 拒绝请求期间的其它工具、改写正文/目标/创建参数或重复操作。目标聊天会按其自身权限处理收到的文本；只向可信设备开放控制面板。

只允许一个协调请求在途。请求 ID 与文本/目标写入 `.local\relay-ledger.json`，含未知状态，跨重载去重；不自动重发。收据存储达到 1000 条会拒绝新请求，避免自动丢弃去重证据。该文件含发送文本，应作为私有数据保护。超时显示结果未知，可能仍在 App 排队；检查协调会话后再决定新请求，不能把未知当失败随意重试。

实时列表直接解析实际 App 工具结果中的 JSON，不使用 mock 列表或模型编写的替代数据；发送前再精确查询目标。App 工具变化或缺少明确结果时保守拒绝/显示未知。

模型只看到固定请求 ID、目标 ID 与 ASCII 正文引用；pre-tool hook 核验目标查询成功、精确参数及尚未调用后，将引用替换成 ledger 中未经改写的正文（包括换行）。投递工具执行前持久记录授权，任何中断后的不确定调用均不重试。回执通过 originatingMessageId、toolCallId 和 hook 请求上下文关联；迟到的真实接受回执可将未知提升为已接受，旧回执不能清除新请求。自然结束且目标已核验但完全未调用发送工具时，仅允许一次补全工具步骤；abort 不续行。运行时的 `user_initiated` 标签本身不能证明用户手动取消。

协调器自身也在真实树中显示，但选中后只能查看控制面板记录，不能向自身投递。无法关联到请求的停止事件保守显示未知，不把它归因用户手动取消。停止/超时释放串行占位后，原请求仍按 ID 去重，晚到的原工具步骤受 hook 拒绝，不能自动补发未知请求。

关闭服务可停止该协调会话或在无在途请求时重载扩展而不再调用启动工具；不要关闭正在使用的其它项目。

## 验证

`npm test` 覆盖认证、Host/Origin、输入长度、窄接口、串行保护和请求去重。测试替身仅存在测试文件，生产不是演示模式。

`.local\relay-probe-state.json` 保存单次真实链路证据：认证 HTTP 请求、扩展注入得到的 coordinatorMessageId、user.message 事件、实际 `send_session_message` 的成功 ToolResult 与 App 接受回执。`.local\relay-web-verification.json` 保存完整 Web 接口投递、同请求去重和真实 App 回执证据。390×844 手机视口已通过浏览器登录、真实目标选择、草稿编辑与无横向溢出验证。仅向专用测试聊天提交测试，没有向工作项目投递。目标实际处理/回复尚未独立验证，不能将 App 接受等同于“目标收到”。

开发浏览器检查使用 `@playwright/test` 和系统 Edge，先 `npm install` 安装开发依赖，再运行 `node test\mobile-browser.mjs`；它不发送消息。`node test\relay-web-e2e.mjs --submit` 会向代码限定的专用测试聊天提交一条消息，不应日常重复运行。`--verify` 只验证已经存在的请求回执并尝试同 ID 重放（应被去重或拒绝），不会创建新的测试请求。

`node test\visual-layout.mjs` 使用独立临时 HTTP 服务和内存测试账号，基于录制的真实 App 列表/ledger 检查 1915×1032 与 390×844 布局，绝不接触用户账号或投递消息。桌面侧栏274px、输入框772×184px；截图写入 `.local\desktop-preview.png` 和 `.local\mobile-preview.png`。这是视觉检查，不代替实际服务/真实手机端到端验证，也不保证 App 所有状态像素级一致。

`node test\history-browser.mjs` 使用隔离历史fixture检查桌面/手机最近页、更早页滚动锚点、新回复不抢滚动、目标切换竞态及HTML/XSS文本显示，不向工作会话发送消息。`npm test`还覆盖半行、错误schema、截断/替换、目录链接与鉴权。历史自动更新只读取磁盘，不产生模型费用；会话列表刷新及发送仍经过模型中转。

本轮真实8765服务的认证HTTP投递、跨重载同ID去重、实际App原文参数/工具回执及真实页面浏览器检查记录在 `.local\relay-reliability-verification.json`。真实服务截图为 `.local\live-desktop-preview.png` 和 `.local\live-mobile-preview.png`。开发检查通过仅开发配置启用的固定目标工具进行，使用随机临时内存凭据并立即注销，不修改本机账号；交付配置关闭 `verificationEnabled`，不注册该工具、不启用临时认证路径。生产没有开发HTTP接口。异常事件顺序用隔离测试模拟，未为了制造失败中止用户的真实协调运行。
